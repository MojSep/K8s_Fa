 مسیرها و فایل‌های مهم Kubernetes

    مرجع کامل مسیرها بر اساس توزیع‌های استاندارد (kubeadm). در توزیع‌های managed (EKS/GKE/AKS) بعضی مسیرها در دسترس نیستند چون control-plane مدیریت‌شده است.

🗺️ نمای کلی ساختار دایرکتوری
text

/etc/kubernetes/              ← تنظیمات اصلی (control plane + kubelet)
/var/lib/kubelet/             ← state و config kubelet (همه نودها)
/var/lib/etcd/                ← دیتابیس etcd (فقط master)
/var/lib/docker/              ← state Docker (اگر از Docker runtime استفاده شود)
/var/lib/containerd/          ← state containerd (پیش‌فرض مدرن)
/var/log/                     ← لاگ‌های سیستم و کانتینرها
/var/log/pods/                ← لاگ پادها (از symlink کانتینر runtime)
/var/log/containers/          ← symlink به لاگ کانتینرها
/run/                         ← runtime state (socket ها، pid ها)
/opt/cni/bin/                 ← باینری‌های CNI plugin
/etc/cni/net.d/               ← تنظیمات CNI
/usr/local/bin/               ← باینری‌های kubectl/kubeadm (اگر دستی نصب شود)

    cluster: kubernetes
    user: kubernetes-admin

🔧 نکته فنی: این فایل به /etc/kubernetes/admin.conf و symlink در ~/.kube/config قرار می‌گیرد. این فایل معادل root shell روی کلاستر است — هر کسی آن را داشته باشد، می‌تواند هر کاری بکند. در production بعد از bootstrap، آن را جدا و دسترسی‌اش را محدود کنید.
📄 manifests/kube-apiserver.yaml — تنظیمات API Server (Static Pod)
yaml

apiVersion: v1
kind: Pod
metadata:
  name: kube-apiserver
  namespace: kube-system
spec:
  containers:
  - command:
    - kube-apiserver
    - --advertise-address=10.0.0.1
    - --allow-privileged=true
    - --authorization-mode=Node,RBAC
    - --client-ca-file=/etc/kubernetes/pki/ca.crt
    - --enable-admission-plugins=NodeRestriction
    - --etcd-servers=https://127.0.0.1:2379
    - --etcd-cafile=/etc/kubernetes/pki/etcd/ca.crt
    - --etcd-certfile=/etc/kubernetes/pki/apiserver-etcd-client.crt
    - --etcd-keyfile=/etc/kubernetes/pki/apiserver-etcd-client.key
    - --kubelet-client-certificate=/etc/kubernetes/pki/apiserver-kubelet-client.crt
    - --kubelet-client-key=/etc/kubernetes/pki/apiserver-kubelet-client.key
    - --secure-port=6443
    - --service-account-issuer=https://kubernetes.default.svc.cluster.local
    - --service-account-key-file=/etc/kubernetes/pki/sa.pub
    - --service-account-signing-key-file=/etc/kubernetes/pki/sa.key
    - --service-cluster-ip-range=10.96.0.0/12
    - --tls-cert-file=/etc/kubernetes/pki/apiserver.crt
    - --tls-private-key-file=/etc/kubernetes/pki/apiserver.key
    image: registry.k8s.io/kube-apiserver:v1.29.x
    # ...

🔧 نکات فنی مهم:

    Static Pod است؛ kubelet این فایل را مستقیم watch می‌کند و تغییرات را بلافاصله اعمال می‌کند.

    --authorization-mode=Node,RBAC — استاندارد امنیتی؛ همیشه این را داشته باش.

    --enable-admission-plugins=NodeRestriction — کافی نیست؛ در production PodSecurity، ResourceQuota، LimitRanger هم اضافه کن.

    --service-cluster-ip-range — تغییرش بعد از bootstrap تقریباً غیرممکن است.

📄 manifests/etcd.yaml — تنظیمات etcd
yaml

spec:
  containers:
  - command:
    - etcd
    - --advertise-client-urls=https://10.0.0.1:2379
    - --cert-file=/etc/kubernetes/pki/etcd/server.crt
    - --key-file=/etc/kubernetes/pki/etcd/server.key
    - --data-dir=/var/lib/etcd
    - --listen-client-urls=https://127.0.0.1:2379,https://10.0.0.1:2379
    - --trusted-ca-file=/etc/kubernetes/pki/etcd/ca.crt
    # برای HA:
    - --initial-cluster=master1=https://10.0.0.1:2380,master2=...,master3=...
    - --peer-cert-file=/etc/kubernetes/pki/etcd/peer.crt

🔧 نکات فنی:

    port 2379 = client (API server به آن وصل می‌شود)، 2380 = peer (master to master).

    /var/lib/etcd = تمام state کلاستر. Backup فقط از این دایرکتوری یا etcdctl snapshot save معتبر است.

    etcd یک raft consensus است — تعداد master باید فرد باشد (۳ یا ۵).

    در حالت stacked، etcd روی همان نود API server است؛ در external etcd جداگانه.

  - --cluster-signing-cert-file=/etc/kubernetes/pki/ca.crt

🔧 نکات فنی:

    --allocate-node-cidrs — Pod CIDR را بین نودها تقسیم می‌کند؛ اگر اشتباه تنظیم شود، Podها ارتباط بین‌نودی ندارند.

    --cluster-signing-* — برای CSR API (روتیت cert ها). حذفش certificate renewal را می‌شکند.

    --leader-elect=true — در HA فقط یک instance فعال است.

📁 /var/lib/etcd/ — دیتابیس کلاستر

└── member/

🔧 نکات فنی حیاتی:

    Backup: ETCDCTL_API=3 etcdctl snapshot save /backup/etcd-$(date).db --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key

yaml

apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration

  anonymous:
    enabled: false                  # ⚠️ باید false باشد
  webhook:
    enabled: true

evictionHard:
  memory.available: "100Mi"
  nodefs.available: "10%"
  imagefs.available: "15%"

🔧 نکات فنی بحرانی:
فیلد	مقدار امن	چرا؟
anonymous.enabled	false	جلوگیری از دسترسی بدون auth به kubelet API
authorization.mode	Webhook	تا RBAC روی kubelet API اعمال شود
rotateCertificates	true	renewal خودکار cert کلاستر
serverTLSBootstrap	true	روتیت cert serving
cgroupDriver	با runtime یکی	systemd ↔ containerd (نه cgroupfs)
evictionHard	تنظیم‌شده	جلوگیری از OOM کل نود

⚠️ تست امنیتی: curl -k https://NODE_IP:10250/pods — اگر response داد یعنی anonymous فعال است = نشت اطلاعات.

📄 /etc/containerd/config.toml — بخش‌های مهم:
toml

version = 2
root = "/var/lib/containerd"
state = "/run/containerd"

[grpc]
  address = "/run/containerd/containerd.sock"

[plugins."io.containerd.grpc.v1.cri"]
  sandbox_image = "registry.k8s.io/pause:3.9"
  enable_selinux = false
  max_container_log_line_size = 16384

  [plugins."io.containerd.grpc.v1.cri".containerd]
    snapshotter = "overlayfs"
    default_runtime_name = "runc"

    [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
      runtime_type = "io.containerd.runc.v2"

      [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options]
        SystemdCgroup = true       # ⚠️ باید با kubelet cgroupDriver یکی باشد

  [plugins."io.containerd.grpc.v1.cri".registry]
    [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
      [plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
        endpoint = ["https://mirror.internal/", "https://registry-1.docker.io"]

  [plugins."io.containerd.grpc.v1.cri".registry.configs]
    [plugins."io.containerd.grpc.v1.cri".registry.configs."registry.internal".auth]
      username = "robot"
      password = "xxx"

  [plugins."io.containerd.grpc.v1.cri".cni]
    bin_dir = "/opt/cni/bin"
    conf_dir = "/etc/cni/net.d"

🔧 نکات فنی بحرانی:

    SystemdCgroup = true باید با cgroupDriver: systemd در kubelet یکی باشد. اختلاف باعث OOM، memory limit بی‌اثر، و pod restart می‌شود.

    sandbox_image باید با نسخه kubelet سازگار باشد (pause 3.9 برای K8s 1.27+).

    snapshotter — overlayfs پیش‌فرض؛ native برای debug، btrfs/zfs اگر FS مناسب است.

    config_path در kubelet (--config-dir=/etc/containerd/certs.d) روش جدید و بهتر برای registry mirror است (جدا از config.toml).

🔀 بخش ۳: فایل‌های مشترک و محیطی
📁 ~/.kube/config
yaml

apiVersion: v1
kind: Config
clusters: [...]
users: [...]
contexts: [...]
current-context: production
preferences: {}

🔧 نکات فنی:

    default path: $HOME/.kube/config، قابل override با KUBECONFIG.

    multi-file: KUBECONFIG=/a:/b:/c → ادغام می‌شود.

    دسترسی: chmod 600 ~/.kube/config (K8s خودش بررسی می‌کند).

    command مفید: kubectl config view --raw (کلیدهای کامل را نشان می‌دهد)، kubectl config get-contexts.

📁 /etc/hosts — برای hostname resolution
text

127.0.0.1   localhost
10.0.0.1    master1
10.0.0.2    worker1
10.0.0.3    worker2

🔧 نکته فنی: kubelet و kube-apiserver در HA به هم با hostname/CNI احتیاج دارند. اگر cert ها با DNS name صادر شده باشند، /etc/hosts باید همگام باشد یا DNS داخلی داشته باشی.
📁 /etc/hostname و /etc/resolv.conf
bash

# /etc/hostname
worker1

🔧 نکته فنی: نام نود (node name) از hostname می‌آید (mگر --hostname-override). تغییر hostname بعد از join = orphan node در کلاستر.
📁 /etc/sysctl.d/ — تنظیمات kernel (خیلی مهم برای networking)
bash

# /etc/sysctl.d/99-kubernetes-cri.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
net.ipv4.conf.all.forwarding        = 1

# برای performance
fs.inotify.max_user_watches         = 524288
fs.inotify.max_user_instances       = 512
fs.file-max                         = 2097152
vm.max_map_count                    = 262144

# برای کلاسترهای بزرگ
net.ipv4.neigh.default.gc_thresh1   = 4096
net.ipv4.neigh.default.gc_thresh2   = 8192
net.ipv4.neigh.default.gc_thresh3   = 16384

🔧 نکات فنی:

    ip_forward=1 — بدون آن، پادها به هم route نمی‌شوند.

    bridge-nf-call-iptables=1 — بدون آن، kube-proxy iptables درست کار نمی‌کند.

    gc_thresh — در کلاسترهای >1000 پاد ضروری است (ARP table overflow).

    اعمال: sysctl --system

📁 /etc/modules-load.d/
bash

# /etc/modules-load.d/k8s.conf
overlay
br_netfilter

🔧 نکته فنی: overlay برای storage driver، br_netfilter برای iptables bridge. بدون br_netfilter، sysctl های بالا بی‌اثر می‌شوند (no file or directory error).

💾 Backup ضروری (روزانه)
bash

# ۱. etcd snapshot
ETCDCTL_API=3 etcdctl snapshot save /backup/etcd-$(date +%F).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# ۲. PKI
tar czf /backup/pki-$(date +%F).tgz /etc/kubernetes/pki/

# ۳. manifests و configs
tar czf /backup/etc-k8s-$(date +%F).tgz \
  /etc/kubernetes/manifests/ \
  /etc/kubernetes/*.conf

# ۴. خود etcd (بعد از snapshot برای verify)
etcdctl snapshot status /backup/etcd-$(date +%F).db

🎯 چکیده نهایی
text

Control Plane (Master):
  /etc/kubernetes/           → تنظیمات و PKI
  /etc/kubernetes/manifests/ → static pods
  /var/lib/etcd/             → state کلاستر (⚠️ backup)

Worker Node:
  /var/lib/kubelet/          → config و state kubelet
  /etc/containerd/           → runtime config
  /etc/cni/net.d/            → شبکه
  /opt/cni/bin/              → باینری‌های CNI
  /var/log/pods/             → لاگ‌ها

همه نودها:
  /etc/sysctl.d/             → kernel params
  /etc/modules-load.d/       → kernel modules
  /run/*.sock                → sockets (tmpfs)

    💡 قانون طلایی: وقتی دیباگ می‌کنی، همیشه از این ترتیب شروع کن:
    kubectl describe → kubectl logs → journalctl -u kubelet → crictl ps/logs → بررسی مسیرهای بالا.
