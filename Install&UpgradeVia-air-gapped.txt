📦 بخش ۱: نصب Air-Gapped (بدون اینترنت)

    سناریو: کلاستر production در محیط ایزوله. تمام artifact ها ابتدا روی bastion (با اینترنت) جمع می‌شوند، سپس به محیط ایزوله منتقل می‌شوند.

🗺️ معماری Air-Gapped
text

┌────────────────────┐              ┌─────────────────────┐
│  BASTION (internet)│              │  ISOLATED DC        │
│                    │   USB/DVD    │                     │
│  - Downloads       │─────────────▶│  - bastion-local    │
│  - Bundle builder  │              │  - registry.local   │
│                    │              │    (Harbor)         │
└────────────────────┘              │  - master1/2/3      │
                                    │  - worker1/2        │
                                    └─────────────────────┘

Artifact های لازم:
نوع	مورد	حجم تقریبی
.deb	containerd, runc, kubelet, kubeadm, kubectl, crictl	~100MB
Image	kube-apiserver, controller-manager, scheduler, proxy, pause, etcd, coredns	~1.5GB
Image	Calico (یا Cilium)	~500MB
Image	CSI Driver (اگر لازم)	~200MB
Manifest	kubeadm, calico, networkpolicy	~50KB
Binary	helm, crictl, etcdctl	~150MB

۱.۲ — دانلود .deb packages
bash

# ساخت repo محلی موقت
mkdir -p /opt/k8s-bundle/deb
cd /opt/k8s-bundle/deb

# Kubernetes repo
curl -fsSL https://pkgs.k8s.io/core:/stable:/v${K8S_MINOR}/deb/Release.key | \
  gpg --dearmor -o /tmp/kubernetes-apt-keyring.gpg

cat > /etc/apt/sources.list.d/kubernetes.list <<EOF
deb [signed-by=/tmp/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v${K8S_MINOR}/deb/ /
EOF

# containerd repo (Docker)
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  gpg --dearmor -o /tmp/docker-apt-keyring.gpg
cat > /etc/apt/sources.list.d/docker.list <<EOF
deb [signed-by=/tmp/docker-apt-keyring.gpg] https://download.docker.com/linux/ubuntu jammy stable
EOF

apt-get update

# دانلود همه package ها با dependency
apt-get install -y --download-only --print-uris \
  kubelet kubeadm kubectl containerd.io 2>&1 | \
  awk -F"'" '/^.?http/ {print $2}' > /tmp/urls.txt

# دانلود واقعی:
cd /opt/k8s-bundle/deb
cat /tmp/urls.txt | xargs -I{} -P5 wget -q {}

# ✅ چک:
ls /opt/k8s-bundle/deb/*.deb | wc -l
# انتظار: 15-25 فایل

dpkg-deb -W --showformat='${Package} ${Version}\n' /opt/k8s-bundle/deb/*.deb | \
  grep -E "kubelet|kubeadm|kubectl|containerd"
# انتظار: kubelet 1.31.2-1.1  kubeadm 1.31.2-1.1  kubectl 1.31.2-1.1  containerd.io 1.7.22-1

۱.۷ — انتقال به محیط ایزوله
bash

# روی bastion اینترنتی → USB یا scp به bastion ایزوله:
scp /opt/k8s-bundle-v1.31.2.tar.gz \
    /opt/k8s-bundle-v1.31.2.tar.gz.sha256 \
    user@bastion-local.internal:/opt/

# روی bastion ایزوله — اعتبارسنجی:
sha256sum -c /opt/k8s-bundle-v1.31.2.tar.gz.sha256
# انتظار: /opt/k8s-bundle-v1.31.2.tar.gz: OK

cd /opt
tar xzf k8s-bundle-v1.31.2.tar.gz
cd k8s-bundle
sha256sum -c SHA256SUMS 2>&1 | grep -v "OK$" | head -5
# انتظار: هیچ خروجی (همه OK)

۲.۳ — Push image ها به Harbor
bash

cd /opt/k8s-bundle/images

# تابع کمکی برای retag + push
for tarfile in *.tar; do
  # خواندن source image از filename
  src=$(echo "$tarfile" | sed 's/\.tar$//; s/__/\//g')
  # نام جدید: registry.local/k8s/<name>:<tag>
  basename=$(echo "$src" | awk -F/ '{print $NF}')
  dst="registry.local/k8s/${basename}"

  echo "→ $src → $dst"
  docker load -i "$tarfile"
  docker tag "$src" "$dst"
  docker push "$dst"
done

# ✅ چک:
curl -s -u admin:'Harbor12345!' \
  "http://registry.local/api/v2.0/projects/k8s/repositories?page_size=100" | \
  jq -r '.[].name' | sort
# انتظار: k8s/etcd, k8s/kube-apiserver, k8s/kube-controller-manager,
#         k8s/kube-proxy, k8s/kube-scheduler, k8s/pause, k8s/coredns,
#         k8s/tigera-operator, k8s/node, k8s/cni, k8s/kube-controllers, ...

۳.۵ — کانفیگ containerd برای private registry
bash

# روی هر نود — حذف تصویر sandbox از registry عمومی و استفاده از local:
grep -q "SystemdCgroup = true" /etc/containerd/config.toml && \
  echo "✅ SystemdCgroup already set" || \
  sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

# ⚠️ مهم: pause image را به registry local تغییر بده
sed -i 's|sandbox_image = ".*"|sandbox_image = "registry.local/k8s/pause:3.10"|' /etc/containerd/config.toml

# اضافه کردن config.d برای registry.local (HTTP نه HTTPS):
mkdir -p /etc/containerd/certs.d/registry.local
cat > /etc/containerd/certs.d/registry.local/hosts.toml <<EOF
server = "http://registry.local"

[host."http://registry.local"]
  capabilities = ["pull", "resolve", "push"]
  skip_verify = true
EOF

# فعال‌سازی config_path
grep -q 'config_path = "/etc/containerd/certs.d"' /etc/containerd/config.toml || \
  sed -i 's|\[plugins."io.containerd.grpc.v1.cri".registry\]|[plugins."io.containerd.grpc.v1.cri".registry]\n    config_path = "/etc/containerd/certs.d"|' /etc/containerd/config.toml

# ✅ چک:
grep -E "SystemdCgroup|sandbox_image|config_path" /etc/containerd/config.toml
# انتظار:
#   SystemdCgroup = true

# علت رایج: cgroup driver mismatch

🎯 Best Practices عملیاتی
Air-Gapped

    همیشه SHA256SUMS بگیر و verify کن — یک USB آلوده، کل کلاستر را آلوده می‌کند.

    Harbor با Trivy — قبل از push به registry، image ها را scan کن (trivy image --severity HIGH,CRITICAL).

    Harbor در HA — در production، Harbor را با external PostgreSQL + S3/MinIO راه‌اندازی کن، نه embedded.

    تصویر pause را با crictl pull قبل از kubeadm init تست کن — این اولین چیزی است که kubelet pull می‌کند.

    tag تمام image ها را pin کن — :latest در air-gap ممنوع.

    نسخه‌بندی bundle — k8s-bundle-v1.31.2.tar.gz + SHA + CHANGELOG.

Upgrade

    هرگز skip minor — 1.31 → 1.32 → 1.33 نه 1.31 → 1.33.

    Backup etcd اجباری — بدون آن، rollback ممکن نیست.

    اول master بعد worker — worker تا ۲ minor می‌تواند عقب باشد.

    drain قبل از kubelet upgrade — پادها با نسخه kubelet جدید rebuild می‌شوند.

    PDB فعال داشته باش — drain روی workloadهای حساس بدون PDB باعث downtime می‌شود.

    maintenance window — حتی با HA، در ساعات کم‌ترافیک.

    upgrade در staging اول — همان نسخه، همان manifest.

    cordon/uncordon سریع — بین drain و uncordon بیش از ۵ دقیقه فاصله نباشد.

    monitor در حین upgrade — kubectl get events -w و kubectl get pods -A -w در کنار.

    CHANGELOG بخوان — Kubernetes release notes برای breaking changes.
